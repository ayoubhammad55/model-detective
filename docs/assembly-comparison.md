# Assembly Comparison: x86-64 vs AArch64

## 1. Objective

The goal of this experiment is to understand how a C implementation of logistic regression inference is translated into machine assembly for different processor architectures and optimization levels.

## 2. Compiler toolchains

### Native x86-64

- Compiler: GCC 13.2.0 (MinGW-w64)
- Target: `x86_64-w64-mingw32`
- Host operating system: Windows

### Cross-compiler for ARM64

- Compiler: Arm GNU Toolchain 15.3.1
- Target: `aarch64-none-linux-gnu`
- Host operating system: Windows

The ARM assembly was generated by cross-compiling the same C source code without requiring physical ARM hardware.

## 3. Generated assembly files

| File | Architecture | Optimization |
|---|---|---|
| `inference_O0.s` | x86-64 | `-O0` |
| `inference_O2.s` | x86-64 | `-O2` |
| `inference_ARM_O0.s` | AArch64 | `-O0` |
| `inference_ARM_O2.s` | AArch64 | `-O2` |

## 4. Instruction comparison

The x86-64 assembly uses instructions such as `movsd`, `mulsd`, and `addsd` for double-precision floating-point operations.

The AArch64 assembly uses instructions such as `ldr`, `str`, `fmul`, and `fadd`.

Both implementations perform the same logical operations:

1. Load model parameters and input features.
2. Calculate the linear score.
3. Apply the sigmoid function using `exp()`.
4. Compare the probability with the classification threshold.
5. Print the prediction.

## 5. Effect of compiler optimization

The optimized AArch64 assembly contains an `fmadd` instruction that combines multiplication and addition.

This can reduce the number of separate arithmetic instructions. Fused multiply-add also has different rounding semantics from separate multiplication and addition.

The optimized assembly still calls the `exp()` library function, so the sigmoid calculation is not implemented entirely by a single processor instruction.

## 6. Limitations

Assembly file size and instruction count alone do not establish execution speed, energy consumption, or overall efficiency.

The assembly files are generated for different target architectures and operating-system environments. A fair performance comparison would require suitable executable builds, controlled measurements, and equivalent workloads.

## 7. Conclusion

This experiment demonstrates the transition from a trained Python model to C inference and architecture-specific assembly. It also illustrates how compiler optimization can change the instruction sequence while preserving the intended computation.
